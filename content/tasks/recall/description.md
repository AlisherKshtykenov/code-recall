# recall (полнота)

**Что делает.** Показывает, какую долю настоящих объектов класса модель нашла: из всех бракованных деталей — сколько она назвала бракованными.

## Как применять

### Как это делают в жизни

```python
from sklearn.metrics import recall_score            # готовая функция из sklearn

y_true = [1, 0, 1, 1, 0, 1]                          # настоящие ответы: 1 — брак, 0 — норма
y_pred = [1, 0, 0, 1, 0, 1]                          # что сказала модель
recall_score(y_true, y_pred)                         # 0.75: нашли 3 брака из 4

recall_score(y_true, y_pred, pos_label=0)            # полнота для класса «норма»
recall_score(y_mc_true, y_mc_pred, average="macro")  # несколько классов: среднее полнот по классам
```


### Параметры `sklearn.metrics.recall_score`

| Параметр | По умолчанию | Что значит |
|---|---|---|
| `y_true` | — | настоящие метки классов |
| `y_pred` | — | предсказанные метки (не вероятности! сначала порог) |
| `labels` | `None` | какие классы считать и в каком порядке; `None` — все, что встречаются, по возрастанию |
| `pos_label` | `1` | положительный класс при `average="binary"` |
| `average` | `"binary"` | `"binary"` — один положительный класс; `None` — массив по классам; `"micro"` — общий TP / общий (TP+FN); `"macro"` — среднее по классам; `"weighted"` — среднее, взвешенное числом объектов класса (support, поддержка); `"samples"` — только multilabel |
| `sample_weight` | `None` | вес каждого объекта |
| `zero_division` | `"warn"` | что вернуть, если у класса нет ни одного настоящего объекта: `"warn"` — 0 и предупреждение `UndefinedMetricWarning`, или `0`, `1`, `np.nan` |

Эталон повторяет все параметры, кроме multilabel-входа (матрица меток) — там нужен `average="samples"`.


### Подводные камни

1. **Recall без precision (точности) обманчив.** «Всё — брак» даёт recall = 1. Смотрите вместе с precision или f1, а для порога — PR-кривую.
2. **`pos_label` для строковых меток.** `recall_score(["брак", "ок"], …)` упадёт: по умолчанию положительный класс — `1`. Передайте `pos_label="брак"`.
3. **`average="binary"` на нескольких классах** — ошибка, а не «как-нибудь посчитает». Явно выберите `macro` (все классы равны) или `weighted` (крупные классы важнее).
4. **Нет настоящих положительных.** В маленьком батче без брака recall не определён — sklearn вернёт 0 с предупреждением. В отчётах задавайте `zero_division` явно.

## Как работает

$$\text{recall} = \frac{TP}{TP + FN}$$

TP (true positive, верно найденные) — брак, который модель назвала браком; FN (false negative, пропущенные) — брак, который модель пропустила.

**Идея.** Из всего настоящего брака считаем, какую долю модель назвала браком.

1. Для каждого класса из матрицы ошибок берём TP (диагональ) и все настоящие объекты класса (сумма строки).
2. recall класса = TP / настоящих; если настоящих нет — значение `zero_division` (и предупреждение при `"warn"`).
3. `binary` — только положительный класс; `micro` — общий TP / все настоящие; `macro` — среднее по классам; `weighted` — среднее с весами по числу настоящих.

## Задача

**Режим «Библиотека»** — примените `sklearn.metrics.recall_score` с той же сигнатурой, что в «С нуля»: тесты проверяют, что вызвано `recall_score`; в `recall_score(…)` явно передайте `average=`, `zero_division=`. Это учит, как и где применять.

**Режим «С нуля»** — напишите `recall_score` своими руками в `solution.py` — **та же сигнатура и тот же результат**, что у sklearn, включая ошибки и предупреждения.
TP и число настоящих объектов класса берите из своей матрицы ошибок: `from bricks.confusion_matrix import confusion_matrix`.
Можно numpy (сравнения, `sum`, `unique`, индексация). Нельзя `sklearn`, `torchmetrics` и любые готовые функции полноты.
В конце файла — `metric = recall_score`: так кирпичик реализует слот **metric**.

Общие тесты (сравнение с библиотекой на многих случаях) должны пройти оба режима.
